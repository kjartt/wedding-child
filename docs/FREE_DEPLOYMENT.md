# Бесплатный запуск свадебной диаграммы

Решение: **приватная Google Sheets → Cloudflare Worker → React-диаграмма**.
Worker и собранный frontend размещаются вместе на бесплатном адресе
`https://wedding-child.<ваш-поддомен>.workers.dev`.
Отдельный сервер Render, платный домен, база данных и подписка Workers Paid не нужны.

Код подготовлен для этой схемы. Создание аккаунтов, настройку новой таблицы,
загрузку secrets и публикацию выполняет владелец по шагам ниже.
Локальные тесты не заменяют проверку опубликованного Worker на бесплатном тарифе.

> Для доступа из российских сетей используйте Render как публичную точку входа по
> [отдельной инструкции](RENDER_GATEWAY.md). Cloudflare Worker при этом остаётся закрытым
> от прямого обращения браузера за Render rewrite; стили и polling не меняются.

## 1. Как сохранить стоимость 0

- В Cloudflare используйте **Workers Free**. Не подключайте Workers Paid и дополнительные платные продукты.
- Используйте предоставленный адрес `workers.dev`; покупать домен не нужно.
- Google Sheets API предоставляется без дополнительной платы; для этой схемы не требуется подключать платные Google Cloud ресурсы.
- Публикация выполняется с вашего компьютера. GitHub Actions и Cloudflare Builds не требуются.
- В коде нет KV, D1, R2, Durable Objects, Cron Triggers или платного мониторинга.
- По документации на 10.09.2026 Workers Free: **100 000 запросов/сутки на аккаунт**, **10 мс CPU на вызов**.
  Ожидание сети не равно CPU-времени. При превышении дневного лимита Free возвращает ошибку, а не покупает дополнительные запросы.
- Один экран при интервале 10 секунд: до 8 640 API-запросов/сутки, за 8 часов — около 2 880.
  Для 1–5 экранов есть запас. Для 100 постоянно открытых телефонов за 8 часов получится около 288 000 — этот сценарий не помещается в лимит.
- Обычные запросы статических ресурсов не расходуют квоту вызовов Worker. Не включайте дополнительные режимы Workers Caching/Worker-first для всех файлов.
- Встроенный Cache API сокращает чтения Sheets, но не отменяет API-запросы браузеров к Worker.
  Его кэш локален для дата-центра, может быть вытеснен и не является постоянной базой данных.
- Бесплатный тариф не гарантирует доступность без сбоев. Проверьте адрес через интернет площадки и мобильную сеть заранее.

Источники: [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/),
[Workers limits](https://developers.cloudflare.com/workers/platform/limits/),
[Sheets API limits и стоимость](https://developers.google.com/workspace/sheets/api/limits).

## 2. Создать таблицу

1. Откройте [Google Sheets](https://sheets.google.com) под своим Google-аккаунтом и создайте пустую таблицу.
2. Назовите файл, например, «Свадьба — подарки».
3. Переименуйте первый лист в **Итоги**. Имя листа внизу экрана отличается от имени всего файла.
4. Заполните ячейки:

   | Ячейка | Значение |
   | --- | --- |
   | A1 | Мальчик |
   | B1 | Девочка |
   | A2 | 0 |
   | B2 | 0 |

5. Выделите A2:B2 и выберите числовой или денежный формат. Вводите **числа**, например `1500`, а не текст `1500 руб.`.
   Денежный формат может показывать символ ₽, это нормально: API читает исходное число.
6. В «Данные → Проверка данных» задайте для A2:B2 условие **число больше или равно 0** и отклонение неверного ввода.
7. Не оставляйте итоговые ячейки пустыми. При отсутствии подарков в обеих должны быть именно нули.
8. Для первоначальной проверки можно поставить A2 = 100 и B2 = 300. Экран должен показать 25% и 75%.
   Перед мероприятием верните нули или реальные суммы.
9. Скопируйте ID таблицы из адреса:

   `https://docs.google.com/spreadsheets/d/ВОТ_ЭТО_ID/edit#gid=0`

   Нужен фрагмент между `/d/` и `/edit`, а не `gid` и не весь URL.

**Самый простой рабочий процесс:** один ответственный редактирует две итоговые суммы A2 и B2.

### Если нужен журнал подарков

Это необязательно. Чтобы не пересчитывать итоги вручную:

1. Создайте второй лист **Подарки**.
2. В A1 напишите «Мальчик», в B1 — «Девочка».
3. Каждый новый подарок записывайте числом в следующую свободную строку нужного столбца.
4. На листе **Итоги** замените A2 формулой `=SUM('Подарки'!A2:A)`,
   B2 — `=SUM('Подарки'!B2:B)`.
5. Если таблица использует русские имена функций, выберите функцию «СУММ» в подсказке формул
   или используйте `=СУММ('Подарки'!A2:A)` и аналогично для B.
6. Защитите формулы A2:B2 через «Данные → Защитить листы и диапазоны».
   Ответственные за ввод должны редактировать журнал, а не формулы итогов.

Убедитесь, что формулы возвращают два неотрицательных числа, без `#REF!`, `#VALUE!` и других ошибок.
Сервер намеренно не превращает ошибку формулы или пустую ячейку в нулевую сумму.

## 3. Настроить доступ Google

Если у вас уже есть рабочий сервисный аккаунт из прежнего backend, его можно использовать повторно:
достаточно предоставить ему доступ к новой таблице. Создавать новый ключ только из-за миграции не требуется.

Если начинаете с нуля:

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) и создайте проект, например `wedding-display`.
2. В выбранном проекте откройте «APIs & Services → Library», найдите **Google Sheets API** и включите его.
3. Откройте «IAM & Admin → Service Accounts → Create service account».
4. Назовите аккаунт `wedding-reader`. Не назначайте проектные роли Owner или Editor:
   разрешение на чтение конкретной таблицы будет предоставлено отдельно.
5. Откройте созданный аккаунт → «Keys → Add key → Create new key → JSON».
6. Сохраните скачанный JSON в приватном месте **вне репозиториев**.
7. Из JSON понадобятся `client_email` и `private_key`. Не публикуйте JSON и не вставляйте ключ в frontend.
8. Вернитесь в таблицу → «Настройки доступа / Share», добавьте `client_email` как **Читатель / Viewer**.
9. Общий доступ оставьте **Ограниченный / Restricted**. «Публиковать в интернете» не нужно.
10. Людям, которые будут вносить подарки, отдельно предоставьте доступ редактора.

OAuth consent screen для входа гостей и Google Drive API этой схеме не нужны.
Если администратор Google Workspace запретил создание ключей, не обходите это ограничение:
нужен разрешённый аккаунт/проект или согласование администратора.

Инструкция Google: [создание сервисного аккаунта и ключа](https://developers.google.com/workspace/guides/create-credentials).

## 4. Подготовить компьютер

Установите Node.js **24 LTS** с [официального сайта](https://nodejs.org/).
Установите Git, затем скачайте оба репозитория (URL можно скопировать на странице каждого
репозитория GitHub):

```powershell
git clone https://github.com/kjartt/wedding-child.git
git clone https://github.com/kjartt/wedding-child-backend.git
```

Для приватных репозиториев GitHub при клонировании попросит авторизацию; пароль аккаунта вместо
токена не используется. Если у вас уже настроен SSH-ключ, можно взять SSH-адреса из **Code → SSH**.
Старые `node_modules`, `dist`, `.dev.vars` и JSON-ключ переносить не нужно.
Новый JSON-ключ сервисного аккаунта создайте по разделу 3, а старый ключ после успешной миграции
удалите в Google Cloud, если старое устройство больше не находится под вашим контролем.

Оба каталога должны лежать рядом и называться так:

```text
programming/
  wedding-child/
  wedding-child-backend/
```

В PowerShell из каталога `programming`:

```powershell
cd wedding-child
npm ci
npm test
npm run lint
npm run build
cd ../wedding-child-backend
npm ci
npm test
npm run build
```

Последняя команда — проверка упаковки Worker, **без публикации**.
Она требует готовый `wedding-child/dist`. После изменения frontend всегда сначала пересобирайте его.

Frontend содержит одно оформление: **Олива**. `npm run dev` и `npm run build` ничего не

## 5. Проверить локально

1. В `wedding-child-backend` скопируйте шаблон:

   ```powershell
   Copy-Item .dev.vars.example .dev.vars
   ```

   Если `.dev.vars` уже существует, отредактируйте его, не перезаписывайте шаблоном.

2. Откройте `.dev.vars` и заполните:

   ```dotenv
   GOOGLE_SHEETS_ID="ID_ВАШЕЙ_ТАБЛИЦЫ"
   GOOGLE_CLIENT_EMAIL="wedding-reader@ВАШ_ПРОЕКТ.iam.gserviceaccount.com"
   GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nВАШ_КЛЮЧ\n-----END PRIVATE KEY-----\n"
   GOOGLE_SHEETS_RANGE="'Итоги'!A2:B2"
   ```

   Для ключа скопируйте значение `private_key` из JSON целиком, сохраняя `\n`.
   Не копируйте имя поля `private_key:` и весь JSON-объект.
   Настоящий ключ нельзя оставлять в примерах документации.

3. Запустите:

   ```powershell
   npm run dev
   ```

4. Откройте [локальное приложение](http://127.0.0.1:8787/) и
   [локальные данные](http://127.0.0.1:8787/api/values).
5. Измените сумму в таблице и дождитесь обновления. В нормальном режиме это занимает примерно 10–20 секунд.
6. Для разработки с автоматическим обновлением React откройте второй терминал:

   ```powershell
   cd ../wedding-child
   npm run dev
   ```

   Откройте адрес из Vite, обычно [http://127.0.0.1:5173/](http://127.0.0.1:5173/).
   Vite перенаправляет `/api` на Worker по порту 8787.

`.dev.vars` игнорируется Git и не загружается в Cloudflare автоматически.
Если `.dev.vars` отсутствует, Wrangler может загрузить старый `.env`.
При наличии `.dev.vars` заполняйте все Google-переменные в нём.
Старые `PORT`, `POLL_MS`, `CORS_ORIGIN`, `VITE_API_BASE_URL` и `BASE_PATH` больше не управляют приложением.

## 6. Разместить бесплатно в Cloudflare

1. Создайте аккаунт на [Cloudflare](https://dash.cloudflare.com/), подтвердите email.
2. В разделе **Workers & Pages** используйте **Workers Free**. Подключать домен и платный тариф не нужно.
3. В `wedding-child-backend/wrangler.jsonc` при желании измените `name`, например на `wedding-andrey`.
   Это имя Worker и часть его адреса. Остальные параметры для стандартной схемы уже готовы.
4. Из `wedding-child-backend` выполните:

   ```powershell
   npx wrangler login
   ```

   Браузер откроет авторизацию Cloudflare. Войдите в свой аккаунт и разрешите Wrangler публикацию.
5. Убедитесь, что frontend собран, затем:

   ```powershell
   npm run build
   npm run deploy
   ```

6. Wrangler напечатает адрес вида `https://wedding-child.<поддомен>.workers.dev`.
   При первом запуске может потребоваться выбрать аккаунт или создать бесплатный поддомен Workers.
7. Откройте Cloudflare → Workers & Pages → ваш Worker → **Settings → Variables and Secrets**.
8. Добавьте три переменные с типом **Secret**:

   | Имя | Значение |
   | --- | --- |
   | GOOGLE_SHEETS_ID | ID из адреса таблицы |
   | GOOGLE_CLIENT_EMAIL | client_email сервисного аккаунта |
   | GOOGLE_PRIVATE_KEY | private_key целиком с BEGIN/END PRIVATE KEY |

   В поле ключа можно вставить PEM с настоящими переносами строк или значение с буквальными `\n`.
   В панели Cloudflare не добавляйте внешние кавычки, которые нужны в dotenv-файле.

9. Примените изменения кнопкой сохранения/deploy в панели.
10. Диапазон `'Итоги'!A2:B2` уже задан в `wrangler.jsonc`. Если ваш лист называется иначе,
    измените диапазон **в этом файле** и повторите `npm run deploy`.
    Настройки, изменённые только в панели, могут быть перезаписаны следующей публикацией конфигурации.
11. Откройте `https://ВАШ_АДРЕС/api/values`. Должны быть `a`, `b`, `fetchedAt` и `stale: false`.
    До добавления secrets API закономерно отвечает 503: frontend опубликован, но чтение Google ещё не настроено.
12. Откройте корень сайта и проверьте диаграмму.
13. В панели убедитесь, что тариф остался **Workers Free**.

Секреты сохраняются при последующих обычных публикациях того же Worker.
Смена имени Worker создаёт другое приложение, которому secrets нужно настроить отдельно.

Не выполняйте `npm start` в панели Cloudflare: это локальная команда.
В облаке Worker сам вызывается HTTP-запросами, постоянного процесса и порта 8080 нет.

Официальные инструкции: [Wrangler CLI](https://developers.cloudflare.com/workers/get-started/guide/),
[Secrets](https://developers.cloudflare.com/workers/configuration/secrets/).

Из `wedding-child`:

```powershell
npm ci

npm run lint
npm run build
cd ../wedding-child-backend
npm ci
npm test

```

После публикации обновите открытую страницу.
Прежний автоматический deployment GitHub Pages заменён ручной проверкой кода:
публикация теперь выполняется через Wrangler. Это исключает обязательное использование облачных CI-минут.

остановите/удалите старый сервис в Render и отключите его платные ресурсы, если они были включены.

## 8. Что проверить до свадьбы

- Проверить 100/300, 0/0 и реальные денежные значения.
- Убедиться, что вкладка доступна гостевому браузеру без входа в Google.
- Проверить интернет площадки и запасной мобильный интернет, включая доступность `workers.dev`.
- Проверить на проекторе/телевизоре полный экран (обычно F11), масштаб и читаемость.
- Оставить экран работать несколько часов; сверить суммы и время обновления.
- В тестовой таблице временно ввести ошибку вместо числа: старые суммы должны сохраниться с предупреждением,
  а после исправления — обновиться. Не проверяйте это во время реального сбора подарков.
- Отключить сеть на устройстве показа: появляется предупреждение, корректные суммы остаются.
  После восстановления сеть снова проверяется автоматически; при backoff ожидание может достигать минуты.
- Зафиксировать версию за день до события и не менять deployment во время показа без необходимости.
- Сохранить скриншот последних сумм или другой локальный резерв и держать запасной интернет.

**Офлайн-ограничение:** localStorage хранит только последние суммы (до 24 часов при восстановлении).
Ресурсы самого сайта не кэшируются service worker. Уже открытый экран переживает потерю сети,
но гарантировать запуск после полного офлайн-перезапуска браузера эта версия не может.
Для резервного локального запуска можно заранее подготовить оба каталога и зависимости;
при недоступном Google новый локальный процесс не получит свежих сумм.

## 9. Если не работает

| Симптом | Что проверить |
| --- | --- |
| 503 сразу после deployment | Все три Google secrets добавлены и сохранены именно в этом Worker |
| Не читается таблица | Sheets API включён; client_email приглашён как Viewer; ID и имя листа верны |
| Старые суммы и предупреждение | Интернет, ошибки формулы, пустые/текстовые/отрицательные ячейки, доступ сервисного аккаунта |
| Локально работает, в облаке нет | .dev.vars не переносится автоматически; повторите настройку secrets в Cloudflare |
| API показывает 0/0 | Проверьте числовые A2:B2 именно в выбранном диапазоне |
| 404 на старом URL | Новый frontend расположен в корне; путь /weddig-child-frontend/ больше не нужен |
| Ошибка 1027 | Исчерпана дневная квота Free; сократите число экранов, дождитесь сброса в 00:00 UTC |
| Ошибка лимита CPU | Проверьте Worker в панели на Free, особенно первый запрос с JWT; не включайте платный тариф автоматически |
| Wrangler не видит assets | Сначала npm run build в wedding-child; каталоги должны лежать рядом |
| Ошибка ключа Google | Полный PEM с BEGIN/END; сохранены переводы строк; ключ не удалён в Google Cloud |
| После исправления нужно ждать | Нажмите «Повторить сейчас»; серверный backoff может сохраняться до минуты |

API намеренно не публикует подробные ошибки Google и содержимое credentials.
`/api/healthz` сообщает, что Worker отвечает; проверять доступ к данным нужно через `/api/values`.

## 10. Обновлённый план архитектуры

1. Использовать бесплатный Worker и Static Assets на одном origin.
2. Читать только две итоговые числовые ячейки приватной таблицы через сервисный аккаунт Viewer.
3. Запрашивать данные по необходимости, с кэшем 10 секунд, а не держать фоновый серверный polling.
4. При ошибке сохранять предыдущий корректный ответ, помечать stale, ограничивать повторы.
5. Проверять контракт на сервере и клиенте; показывать нулевые итоги отдельным состоянием.
6. Хранить ключ только в локальном .dev.vars и Cloudflare Secrets.
7. Собирать и публиковать с компьютера; платные CI, домен, БД и мониторинг не подключать.
8. Проверить опубликованную версию и резервный сценарий на оборудовании площадки.

Render Free и Koyeb Free не выбраны из-за сна после простоя.
Apps Script остаётся альтернативой при недоступности Cloudflare, но потребует другого способа
размещения интерфейса; инструкции выше относятся именно к реализованному Worker.
